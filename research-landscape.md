# Coding-agent and local-inference research landscape

> INTERNAL RESEARCH — as of 2026-09-27. Includes source spot checks and public documentation. Product claims, benchmark claims, and measured behavior are labeled separately. No candidate is a default recommendation without a task-matched evaluation.

## How to read this review

The five baseline source maps cover Claude Code, Codex, Cline, OpenCode, and Aider. The additional candidates named in the research request now each have a separate root-level source note linked below. These are focused architecture/schema/flow audits of high-value public source paths, not claims that every line of each large repository was exhaustively read or formally verified. A README capability is not proof of reliability, security, quality, or low cost. These notes identify patterns and experiments, not adoption decisions.

## Tracking external agents as subagents

**Yes, if the parent owns a durable adapter record.** Assign task and attempt IDs before launch. Persist peer identity, negotiated capabilities, external session/thread ID, event cursor, workspace/base commit, authorization scope, and lifecycle. Normalize only events the peer emits: start, plan/progress, tools, permission, input, artifacts/diff, completion, failure, disconnect, cancel, resume. Save raw protocol payloads as bounded artifacts; canonical state stays in HorizonCode.

What cannot be promised generically:

- ACP streams can be interrupted; load/resume depends on negotiated capability and implementation.
- A subprocess returning only a final response cannot truthfully provide live progress, cost, token count, or nested-child state.
- Children launched inside an external peer are invisible unless it reports their IDs/events.
- Process exit or protocol completion does not mean requested work passed tests.
- Parent attempt and worktree history must survive even if the peer session is ephemeral.

Model the hierarchy as an observability graph: HorizonCode task → adapter attempt → peer session/thread → peer-reported child attempts. Unknown child count and unavailable usage remain explicitly unknown. Enforce HorizonCode permissions/budgets around the process/worktree; peer-reported limits are not a substitute.

Measure peak/steady memory, load time, tokens/sec, queueing, concurrent streams, cancellation, context limits, tool-call correctness, schema adherence, and security. Capture model weights/quantization and prompt template in evidence. Model quality, tokenizer, server template, and parser affect behavior; API compatibility alone is insufficient.

## Evaluation queue for HorizonCode

1. Compare Qwen's external-executor behavior for ACP and one-shot Codex.
2. Compare DeepCode and Ouroboros for goal/intent persistence and recovery; trace source schemas and transactions.
3. Compare Serena and Code Review Graph on HorizonCode's Rust tree: symbol/reference recall, stale-index behavior, write correctness, privacy, and license compatibility.
4. Compare RTK-style output reduction with raw tool output using identical tasks and hidden checks; measure lost-information rate.
5. Compare Superset and ARCH/06 with a multi-repo workflow; track process IDs, leases, diff ownership, and crash recovery.
6. Re-run jcode PSS/RSS tests with pinned binaries and process-tree accounting before making a RAM decision.
7. Test local inference backends against one fixed tool-call/repository benchmark, holding model weights constant where possible.
