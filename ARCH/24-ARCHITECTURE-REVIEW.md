## Migration order and validation gates

1. Reconcile tracker, current source, and acceptance status. Preserve user changes and make no readiness claim from crate presence. Fix F-06/07/08/09 and the audit per-effect gap before unattended execution.
2. Add immutable original intent/spec/decision and task/attempt/evidence event schemas with projection migrations. Retain old session replay and refuse unknown newer events.
3. Add one controller with fenced claims and hierarchical budget reservations. Build crash/effect reconciliation before enabling automatic retries of external effects.
4. Add repository context freshness, local model conformance, ACP external-attempt tracking, and integrated revision verification.
5. Expose configurable operator settings and truthful status across TUI/headless/ACP. Add PR lifecycle only after effect idempotency and policy boundaries are tested.
6. Benchmark against a same-model/same-budget single-agent baseline and publish failures, cost, and acceptance evidence. Preserve the full intended capability set; staging is a dependency order, not a scope cut.

No `ACC-P1-*` record was produced in this review. `ARCH/23` remains the release evidence authority. A proposed task in `TODO.md` is not proof that a requirement is implemented.
