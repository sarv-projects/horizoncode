# 06 — User Interface

Terminal-native, `ratatui`-based. One workspace renderer serves both the default view and the focus workspace. This document is the LLD for `CMP-tui`.

## 1. Surface model

- **Default mode — scrollback-native.** The transcript lives in the terminal's own scrollback (free native search, select, copy, tmux). A **Prompt Bar** (composer · status · todo) is a fixed dock that never moves and never loses a draft. Completed blocks are inserted into scrollback as they commit; only the final block is mutable.
- **Focus workspace — alt-screen.** `F2` / `/focus` enters an alt-screen workspace that stays until toggled off; exiting restores the exact scrollback position. `Ctrl-B` is not a default binding because multiplexers commonly reserve it. Docking exists only here, because only an owned screen can clip and reflow regions.
- **Invariants.** Zero layout shift on commit; append-only transcript; truthful status; the composer is sacred.

## 2. Dockable workspace (`REQ-UI-006`)

### 2.1 Anchors and panels

| Element | Kind | Movable | Closable |
|---|---|---|---|
| Transcript | Anchor (center) | No | No |
| Prompt Bar | Anchor (bottom row) | No | No |
| Explorer, Document, Changes, Timeline, Checkpoints, Context, Agents, MCP, LSP, Todo, plugin panels | Panel | Any zone | Yes (restorable) |

Dock zones: **Left · Right · Bottom**. A side zone may hold two stacked groups (top/bottom); the bottom zone is a single group in v1.

### 2.2 Default layout (focus, ≥ 120 cols)

- **Right** = Explorer (tree).
- **Bottom** = Document (viewer / diff / editor) — full width, because a wide diff is far more readable than a 44-col one.
- **Left** = collapsed. **Center** = transcript.

Fully rearrangeable; layouts are saved.

### 2.3 Dock mechanics

- **Mouse drag:** press a panel title bar → ghost follows cursor → drop-zone mini-map highlights → drop on Left/Right/Bottom; drop on a tab strip reorders within a group; lower-half-of-a-side drop targets that side's second group.
- **Keyboard drag (parity, required):** in panel focus only, `Ctrl-W` is a prefix and `D` enters move mode → arrows move the ghost → `L`/`R`/`B` drop, `Esc` cancel. Also a `/dock` picker overlay. No prefix is intercepted while a text field, editor, terminal, or composer owns focus.
- **Swap sides:** `Ctrl-W` `S`.
- **Collapse/expand:** `Ctrl-W` `C`; collapsed zones shrink to an icon strip (2 cols side, 1 row bottom) and remain informative via badges.
- **Reorder:** drag along the tab strip, or `Ctrl-W` `←`/`→`; `Ctrl-W` `Tab` cycles the active panel.
- **Close/restore:** `Ctrl-W` `X` removes from the zone (emptied zone auto-collapses); the panel stays in the registry, reachable via `/panels`, and re-docks from its picker. Closing never deletes work.
- **Maximize/restore:** `Ctrl-W` `M` or `▣` toggles maximize; covers the workspace, Prompt Bar stays fixed. (A terminal has no floating windows; "float" maps to maximize.)

### 2.4 Panel title bar (top-right controls)

```
┌ Explorer ──────────────────────  −  ▣  ⤢  ⋯  ×  ┐
```

| Button | Action |
|---|---|
| `−` | Collapse / expand |
| `▣` | Maximize / restore |
| `⤢` | Move / dock (opens drop-zone picker) |
| `⋯` | Overflow menu |
| `×` | Close (restorable) |

Narrow title rows collapse to `− × ⋯` (never wrap/truncate ambiguously). Buttons are keyboard reachable; glyphs fall back to ASCII on legacy consoles (Windows-first).

### 2.5 Global toggle bar

One row: product · branch · changed-file count · run state · cost, plus zone toggles `▤ ▥ ▬ ◱` (Left / Right / Bottom / layout menu). `Alt-1..4` jump zones; `Ctrl-W 0` resets layout. Defaults are configurable; at startup, validate bindings per focus context, detect collisions, and offer a safe fallback plus command-palette route for every action.

### 2.6 Focus discipline

`Alt-1..4` focus Left/Transcript/Right/Bottom. **Nothing auto-navigates**: a tool completing never opens a panel, steals focus, or moves the page; a background panel badges instead of popping. One accent per panel; selection uses the semantic accent.

## 3. Responsive rules

| Width | Capability |
|---|---|
| ≥ 160 | Full docking; optional side-by-side diff |
| 120–159 | Full docking; unified diff only |
| 100–119 | Side zones disallowed; Bottom + maximize only |
| 80–99 | No docking; panels render as full-screen screens |
| < 80 | Single-column stack |

Center transcript keeps a protected minimum (60 cols); violating moves auto-collapse the panel or reject the move with an honest message. Sides 24–40 % width, bottom 8 rows–60 % height. Resize via explicit `Ctrl-W` `R` mode or divider drag.

## 4. Persistence and extensibility

- **Light layout record only:** zones, sizes, active panel/tab, maximized panel — ids and geometry, re-derived on load, never durable truth.
- **Panel registry** is the extensibility point:
  ```
  PanelContract { id, title, icon, min_size, default_zone, linked,
                  render(ctx), on_key(ev) -> Handled|Bubble, badge() }
  ```
  Built-ins: `explorer`, `document`, `changes`, `timeline`, `checkpoints`, `context`, `agents`, `mcp`, `lsp`, `todo`.
- Telemetry and server status (`context`, `mcp`, `lsp`) register as panels **closed by default** and open via `/context`, `/usage`, `/mcp`, `/lsp` — satisfying "move the sidebar content behind a command" without losing it.
- The `agents` panel is a controller-backed view of registered profiles and the durable root/child attempt tree (`ARCH/27`). Profile discovery, install staging, trust, enablement, model control, child launch, quota facts, and task verification remain separate actions/services; a panel row cannot edit the canonical task state itself.
- Explorer → Document are **linked** (selecting a file opens/focuses it without stealing focus from a running turn), even across zones.
- Third-party/plugin panels must register through the registry and pass the guard — never a raw hook.

## 5. Explorer panel (worktree)

- Data source: git index + ignore rules; lazy load; virtualized (only visible rows render).
- Live updates: filesystem watcher + incremental tree-sitter parse; worktree indexing never blocks the loop (`REQ-PERF-003`).
- Git status per row: glyph + letter (staged / modified / untracked / conflict); changed-file count badge when collapsed.
- Filter/search with fuzzy matching.

## 6. Document panel (viewer · diff · editor)

One panel, per-file tabs; each tab remembers mode, cursor, scroll, dirty state.

- **View** — syntax highlight (tree-sitter), line-number gutter, soft-wrap allowed.
- **Diff** — unified by default; side-by-side only ≥ 160 cols; gutter line numbers, add/del background bands, dual line numbers; truecolor → 256 → 16 palettes with ANSI-16 falling back to foreground-only; word-level diff is **cut for v1**.
- **Edit** — see §7.

## 7. Embedded mini-editor (`DEC-010`, `REQ-UI-005`)

One governed editing path. Bounded, terminal-appropriate. A governed external-editor handoff and semantic editor adapter are first-class alternatives (`DEC-030`, `REQ-UI-005`).

**In v1:** insert/delete (char/word/line), Enter with auto-indent, `Tab` indent / `Shift-Tab` outdent, selection, copy/cut/paste (OSC 52 + internal register), bounded undo/redo, literal search, go-to-line, standard motions, syntax highlight, gutter.
**Out in v1:** multi-cursor, undo tree, macros, Vim modal bindings, LSP-driven rename/inlay hints.

- **Read-only safety bound:** files > 2 MiB, > 50 000 lines, or binary open **read-only** in the embedded editor with an explicit reason. A governed external-editor handoff remains available after permission and workspace/base-hash checks (`DEC-030`).
- **Keys:** `e` enter edit / `Esc` leave (guarded if dirty); `Ctrl-S` save; `Ctrl-Z`/`Ctrl-Y` undo/redo; `Ctrl-F` search; `Ctrl-G` goto line. Copy and cancel do not share a global binding; keymaps are configurable and collision-checked, with menu/palette access for each action.
- **Soft-wrap:** allowed in view; **off in edit** (horizontal scroll) — persistent display↔buffer line mapping is a known cursor-bug source. Document defaults to the wide Bottom zone, so width is available.
- **Unicode/IME:** display-width aware; never split a grapheme; IME composition is best-effort and documented as a limitation.
- **Performance:** incremental reparse of the edited region only; dirty lines re-rendered only; coalesced input behind a frame-rate limiter; progressive highlight upgrade so a large file never blocks first paint.

## 8. Concurrent edits (user vs agent)

Every save and every agent write goes through **one governed write path**: acquire lease → re-read + hash → compare to base → atomic temp+rename → else **conflict**. No silent overwrite.

- In-editor banner when the file changes on disk: `changed on disk — [Reload] [Compare]`.
- Conflict modal with a non-destructive default.
- Agent-side conflict returns a typed re-apply result.
- Snapshots taken earlier are invalidated when the file changes.

## 9. Long-horizon surfaces (`REQ-HORIZON-*`)

Panels closed by default: `timeline` (progress + background jobs), `checkpoints` (create/rewind), `changes` (changed files at a glance + "what changed since you last looked"), `context` (tokens/%/cost). The Top Bar shows a compact world summary. Every indicator maps to a real event; waiting states are visually distinct from working states (`REQ-HORIZON-004`).

The default header names the current **run**, task and worker/model, branch, verified
criteria count, pending approval, elapsed time, and spend against the selected budget.
The target command registry in `ARCH/27-COMMANDS-AGENTS-SETTINGS.md` owns every `/`
command, syntax, argument schema, availability, and safe failure behavior. `/run`,
`/tasks`, `/agents`, `/settings`, `/usage`, and `/context` open controller-backed
views; commands such as `/resume`, `/cancel`, `/verify`, `/checkpoint`, `/mcp`,
`/skills`, `/plugins`, and `/pr` call only their owning services. Completion, help,
and palette search use that same registry. Unknown or malformed commands never fall
through to a model prompt. The source baseline currently implements only `/usage` and
`/insights` for headless `-p` prompts; the target TUI command list is not shipped.

### Goal draft, preparation, and start review

`/goal set` renders a draft receipt containing the exact user request, selected
workspace, and observed base commit; it does not fabricate acceptance criteria or
silently invoke a planner. `/goal prepare <run-id>` first presents the selected
planner route, read-only repository scope, finite planning cost/time/token budget, and
the fact that it cannot edit files or launch coding peers. After that bounded planning
attempt, the `Goal Review` view shows original request, confirmed requirements,
assumptions/exclusions and open questions, spec/task-graph/plan digests, workspace
base, effective policy snapshot/digest, selected provider/model/agent and capability snapshot, proposed permissions,
total/task/verification/recovery budgets, and expected checks. It provides accessible
`Start`, `Revise`, and `Cancel` actions. Opening the review creates a durable,
expiring challenge bound to this authenticated control session and connection; show
its short challenge ID and expiry with the review digest. Start is disabled while
blocking questions remain or any displayed digest is stale; the user must reopen
review after a route, policy, workspace, spec, graph, plan, or budget change. A newer
review replaces and invalidates an older pending challenge, so two open tabs cannot
confirm different plans for the same goal.

The approval prompt is a durable blocking item, not a notification preference. Start
requires an explicit confirmation bound to every digest in the displayed review
bundle through the same authenticated operator control session that opened the
challenge. Model, tool, peer, plugin,
and recovery principals cannot submit or synthesize this confirmation; command text
and CLI flags alone never grant operator authority. The controller records a
confirmation first, then reserves execution plus mandatory verification/recovery
resources with idempotency keys and commits activation only when reservations are
durable. A durable outbox dispatches from that activation event. A crash or uncertain
launch is reconciled by the same event/attempt IDs; it never opens a duplicate attempt.
Denial, Escape, timeout or client disconnect before the response is durably accepted,
a stale response, or a failed reservation leaves work undispatched,
expires/invalidates the challenge as appropriate, and
retains the exact reason in the timeline. Keyboard, mouse, and screen-reader actions reach the same
typed control service; the rendered confirmation names the affected run and cannot
use color alone to convey consequences. Existing settings can change presentation
colors and alert sound, but cannot hide, approve, or alter this gate. `/goal clear`
clears only a safe session selection pointer as defined in `ARCH/25`.

For ACP approval, the review surface also identifies the configured connector and
its authentication/trust status, and makes clear that the connector—not ACP
wire-format proof—must present the exact bundle and capture the choice. If the
connector has no authenticated operator scope or is not allowlisted as trusted, the
ACP confirmation action is disabled and the user is directed to the trusted local
TUI/CLI control surface. The actor, control session, approval method, and verified
identity (when available) remain visible in the durable timeline. Notification,
sound, and palette settings cannot promote an untrusted connector or disguise the
approval source.

Composer references use `@agent:<id>`, `@file:<path>`, `@task:<id>`, `@run:<id>`,
`@symbol:<name>`, and `@skill:<id>` as documented in `ARCH/27`. A mention supplies a
typed reference or routing intent but never launches a peer, executes a tool, reads a
secret file, or grants authority by itself. An explicit dispatch action creates an
`AgentAttempt` under the controller after budget, policy, and workspace checks.

The queue view shows input receipts, lane,
sequence, age, current owner, retry/cancel state, and whether an input was promoted,
rejected, or remains pending. A worker heartbeat is labeled liveness only.
Changing model or compaction settings records a new context epoch; it does not alter a
prior cost or verification record (`REQ-UI-010..011`, `ARCH/25`).

Provider output is shown as a distinct attempt stream. A complete validated response
becomes the assistant message; truncated/failed bytes stay under an expandable
“incomplete attempt” row with the finish cause, provider/model, token/cost provenance,
retry count, and whether tools were dispatched. If the controller recovers, label the
first fragment superseded and present one final answer, never concatenate partial and
retried text as though the model produced one continuous valid answer. Unknown or
explicit output caps offer bounded next actions and leave the run/task incomplete;
they do not appear as a green completion or trigger a muted background retry. Cancel
remains available while compaction/retry is being admitted.

## 10. Theming and accessibility

- Semantic token set; user-selectable accent with a **cool-blue default**. Selection uses the chosen accent only if it remains distinguishable from reserved warning/error/status hues; state meanings use separate semantic tokens and text/glyphs (`REQ-UI-007..008`).
- Colour level detection (truecolor → 256 → 16); `NO_COLOR`, `TERM=dumb`, reduced-motion honored.
- No meaning is colour-only: every colour carries a glyph/letter (`REQ-UI-008`).
- Everything dockable is keyboard-dockable; focus always visible; explicit resize mode; optional linear screen-reader rendering.
- Keymaps are scoped by focus/context and user-editable. Invalid or colliding changes are rejected with both conflicting actions named. Defaults can be restored through `/settings` or the palette. No essential action depends on colour, mouse, or one shortcut.
- Telemetry uses tabular numerals.

Themes are semantic token palettes with user-editable foreground, background,
selection, border, accent, and decorative tokens; the settings preview shows working,
waiting, denied, failed, approval-pending, budget-stopped, and verified states before
saving. Palette validation checks contrast and keeps selection distinct from reserved
status meanings across truecolor/256/16-colour modes. `NO_COLOR`, `TERM=dumb`, and
reduced-motion settings override decorative choices. `/settings theme` exposes these
values; it shows the effective palette after environment and policy overrides. Every
setting view shows the
effective value, source scope, apply boundary, validation error, and policy lock.
Colour never replaces a text label or glyph for an outcome.

Notification preferences live at `/settings notifications`: per-event in-client
badges, optional terminal bell, optional desktop notification where supported,
quiet-hours batching for non-critical events, and rate limits. Sound can be disabled.
Muted events stay in the durable timeline; a blocking approval or stop state remains
visible on attach even if all external channels are muted. Notification failure never
holds or authorizes a run.

Per-profile primary/worker selection and resource controls live at `/settings agents`
and the Agents panel. The panel shows model identity only when observed/configured by
an adapter, and displays unknown peer usage and hidden nested workers explicitly.
Model, workspace, permission scope, cost source, and quota source are independent
fields. Exact lifecycle and caps are specified in `ARCH/27`.

Session artifacts that are unavailable, corrupt, unsupported, over limit, or refused
by the active model route render as an accessible metadata placeholder: type, bounded
size, digest prefix, verification state and typed reason. The UI never shows raw
base64, an empty image tile, or an executable active-content preview. A placeholder
does not claim the original media was understood, and dependent verification stays
blocked. `/settings session storage` shows encoded/decoded ceilings, current and
reserved bytes, retention, cleanup candidates and the effective filesystem durability
mode; cleanup preview lists owners and refuses deletion if a reference scan is
incomplete. Notifications may be muted, but truncation, unavailable artifacts,
budget stops, and required approvals remain in the durable timeline.

The run/session header also shows current/reserved **event-log bytes separately from
artifact bytes**, segment count, last committed sequence/revision, and whether the
physical emergency reserve is allocated, consumed, or needs replenishment. Approaching
a limit warns before dispatch; a hard storage fence stops new work while preserving the
cancel/reconcile/handoff reserve. Render `storage-pressure`, `reconciling-tail`, and
`event-log-corrupt` with a plain-language reason and last verified event; never use a
spinner or green completion mark for these states. Session/history reads and listing
are visibly read-only; if recovery is needed, offer a distinct recovery action and
show that the original bytes are retained. The UI never silently “repairs” by
truncating the log.

The session picker also preserves uncertainty: unreadable, corrupt, unsupported, or
recovery-pending sessions stay visible with a typed status. If directory/index
enumeration is incomplete, show that the list may be incomplete instead of showing
“no sessions.” Opening a status row does not mutate the session; recovery is an
explicit action with an inspectable outcome.

## 11. Status vocabulary

The display projects **separate** run, task, turn, attempt and external-peer states (`ARCH/25`) into: idle · draft · preparing(plan-only) · awaiting-clarification · ready-for-review · awaiting-start-confirmation · starting/reconciling · cancelling-start(reservation release) · cancelling(target) · reconciling(target/effect) · queued · thinking · working(tool) · awaiting-approval · retrying(reason + attempt) · truncated-incomplete · artifact-unavailable · interrupted · verified-complete · stopped(reason) · error(expandable) · background. A turn's `completed` cannot render as run completion, accepted approval cannot render as active work until `GoalActivated` is committed, and cancellation is not terminal while an external process/effect is unknown. Show the exact target kind/ID and any blocked dependents; do not imply descendant cancellation. Spinners mean a real operation is in flight and stop on completion; retries show reason and attempt; heartbeat indicates liveness only, never progress.

## 12. Feasibility verdict

- **Implementation estimate (unvalidated):** dock zones, collapse/expand, maximize, tab reorder, zone toggles, drag ghost + drop-zone overlay; the editor's core (insert/delete/undo/save/search/highlight) with incremental tree-sitter highlight. No prototype or usability benchmark establishes these estimates yet.
- **Medium:** keyboard-drag parity with mouse; two-group side split; large-file editing; conflict UX; IME.
- **Expensive / capped:** nested splits beyond one-per-side (deferred); editing soft-wrapped text (avoided via h-scroll in edit); multi-cursor/undo tree (cut); untrusted plugin panels (registry + guard only).
- **Cut for v1:** word-level diff, side-by-side below 160 cols, 3-way merge UI, multi-cursor/Vim bindings, binary/image preview, in-tree content search. Governed external-editor handoff is not cut. If an image/binary payload is present in the transcript, render a typed metadata/availability row (type, size, digest prefix, unavailable reason), never a blank tile or raw base64; actual preview stays out of v1 and any later decoder must pass artifact integrity/resource checks first.

Docking is the easier half; the embedded mini-editor is the real cost and is feasible **only** with the bounded scope and the 2 MiB / 50 k-line read-only fallback above. Both decisions are mutually consistent: docking requires the alt-screen, and the editor is happiest in the wide Bottom zone the docking model encourages.
