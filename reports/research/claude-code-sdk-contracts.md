### 1.4 Control-protocol schema

There is **no separately shipped JSON/protobuf control-protocol schema file**. The only JSON files in the package are `package.json`, `manifest.json`, `manifest.zst.json`. `manifest.json` is a *build/binary* manifest, not a protocol schema (fields: `version`, `manifestSignatureEnforcement`, `commit`, `buildDate`, `platforms{…}`, `sdkCompat{testedWrapperVersions, harnessSchema}`).

The control protocol is declared **inside `sdk.d.ts`** (all `declare type`, i.e. not re-exported): `SDKControlRequest`, `SDKControlResponse`, `ControlResponse`, `ControlErrorResponse`, `SDKControlCancelRequest`, `SDKControlRequestInner` (40-member union), and 40 request/response pairs. See §3.6.

### 3.1 Function signature (`SDK-TYPED`, verbatim)


### 3.4 Warm-start API (`SDK-TYPED`)


`DOCUMENTED`: `startup` pre-warms in the known cwd; `prewarm` parks a spare (≈230–260 MB RSS) in a private temp dir under the config dir until `claim()` supplies the session cwd. `prewarm()` throws if `options` sets `resume`/`continue`/`forkSession`. ### 5.5 Exit-code semantics (settings-level hook definition)

`SDK-TYPED` JSDoc inside `Settings.hooks` (the CLI hook config, distinct from SDK callbacks):

> *"What a failure of this hook does: it could not start (a missing script or plugin directory), timed out, **exited with a code other than 0 or 2**, or printed JSON that is invalid or fails validation. `'continue'` (default): the failure is reported and the action goes ahead. `'block'`: the failure counts as **exit code 2**, so the action the event guards (a tool call, a permission request, a prompt) is blocked. Ignored for async hooks and on `Stop`, `SubagentStop`, `TaskCompleted` and `TeammateIdle`."*

> *"`asyncRewake`: If true, hook runs in background and wakes the model on **exit code 2 (blocking error)**. Implies async."*

So the declared semantic is: **exit 0 = success**, **exit 2 = blocking error**, any other code = failure routed through `onFailure` (`'continue'` default, `'block'` to treat as exit 2).

Hook config union (5 kinds) with their own keys:

```ts
{ type:'command';    command: string; args?: string[]; if?: string; shell?: 'bash'|'powershell';
                     timeout?: number; onFailure?: 'continue'|'block'; statusMessage?: string;
                     once?: boolean; async?: boolean; asyncRewake?: boolean }
{ type:'prompt';     prompt: string; if?: string; timeout?: number; model?: string;
                     continueOnBlock?: boolean; statusMessage?: string; once?: boolean }
{ type:'agent';      prompt: string; if?: string; timeout?: number /* default 60 */; model?: string /* default Haiku */;
                     statusMessage?: string; once?: boolean }
{ type:'http';       url: string; if?: string; timeout?: number; onFailure?: 'continue'|'block';
                     headers?: Record<string,string>; allowedEnvVars?: string[]; statusMessage?: string; once?: boolean }
{ type:'mcp_tool';   server: string; tool: string; input?: Record<string,unknown>; /* … */ }
```

`if` uses permission-rule syntax (e.g. `"Bash(git *)"`) to avoid spawning hooks for non-matching calls. `args` switches from shell form to exec form (no shell parsing; `${CLAUDE_PLUGIN_ROOT}` substituted per element).

### 6.3 Starting mode

`permissionMode` omitted → the CLI picks the start mode as it does for `claude -p`: `permissions.defaultMode` from loaded settings, else `'auto'` where that is the default, else `'default'`. Pass `'default'` explicitly to keep manual approvals through `canUseTool`. (`SDK-TYPED` JSDoc; docs say CC ≥ 2.1.302 starts in `default` unless a mode is set.) On a cloud create/attach, `'default'` leaves the session's own mode.

### 6.4 Evaluation order — six steps (`DOCUMENTED`)

This is the **declared** order; it is not inferred from the bundle.

1. **Hooks** (`PreToolUse`). A hook can deny outright. A hook `allow` does **not** skip steps 2–3.
2. **Deny rules** (`disallowedTools` bare names removed earlier; scoped rules checked here). A match blocks **even in `bypassPermissions`**.
3. **Ask rules** (settings `permissions.ask`, plus org-`ask` connector tools and `_meta["anthropic/requiresUserInteraction"]`). A match falls through to `canUseTool` **even in `bypassPermissions`**.
4. **Permission mode** (`bypassPermissions` approves all but critical-path removals; `acceptEdits` approves file ops; `plan` sends edits/shell-writes to `canUseTool` regardless of allow rules).
5. **Allow rules** (`allowedTools` + settings `permissions.allow`). Includes calls a tool approves on its own (in-cwd reads, read-only Bash). A match does **not** approve network-path reads or critical-path removals.
6. **`canUseTool`**. Skipped entirely in `dontAsk` (→ deny) and when `permissionPrompts:'none'` (→ deny, though a `PermissionRequest` hook still gets a chance).

### 6.5 Mode × outcome matrix (as declared)

| Situation | `default` | `dontAsk` | `acceptEdits` | `plan` | `bypassPermissions` | `auto` |
|---|---|---|---|---|---|---|
| Deny rule matches (scoped) | deny | deny | deny | deny | **deny** | deny |
| Ask rule matches | → `canUseTool` | **deny** (no prompt) | → `canUseTool` | → `canUseTool` | **→ `canUseTool`** | → classifier/`canUseTool` |
| File edit inside cwd / `additionalDirectories` | → `canUseTool` | deny unless allowed | **auto-allow** | **→ `canUseTool`** | auto-allow | classifier |
| File edit outside cwd, protected path, or critical-path `rm` | → `canUseTool` | deny | → `canUseTool` | → `canUseTool` | **→ `canUseTool`** (falls through) | mode-dependent |
| Read inside working dirs | auto-allow | auto-allow | auto-allow | auto-allow | auto-allow | auto-allow |
| Read from a network path | → `canUseTool` | **deny** even if allow-listed | → `canUseTool` | → `canUseTool` | → `canUseTool` | mode-dependent |
| `AskUserQuestion` / `requiresUserInteraction` MCP tool | → `canUseTool` | **deny** | → `canUseTool` | → `canUseTool` | **→ `canUseTool`** | → `canUseTool` |
| Org-`ask` connector tool | → `canUseTool` | **deny** | → `canUseTool` | → `canUseTool` | **→ `canUseTool`** | → `canUseTool` |
| Allow rule matches | allow | allow | allow | edits still → `canUseTool` | allow (moot) | allow |
| Nothing matches | → `canUseTool` | deny | → `canUseTool` | → `canUseTool` | allow | classifier → maybe `canUseTool` |

Bold entries are the documented exceptions to the mode's headline behaviour.

> **Provenance.** The six-step order and the per-mode rule statements are `DOCUMENTED` verbatim from the permissions reference. The matrix composes those statements; cells marked **bold** correspond to an explicit documented exception ("even in `bypassPermissions`", "denied instead", "never auto-approved"). No cell is derived from bundle inspection.


### 6.6 Rule forms (`DOCUMENTED`)

| Form | Meaning |
|---|---|
| `Bash` (bare) | Whole tool: in `disallowedTools` it **removes the tool from the request**; in `allowedTools` it auto-approves every call. |
| `Bash(rm *)` | Scoped: tool stays available; matching calls denied in every mode incl. `bypassPermissions`. Bash rules match the command **as written**, so `/bin/rm` does not match `rm *`. |
| `Edit(path)` | Governs **all** built-in write tools incl. `Write` and `NotebookEdit`. A `Write(path)` rule is never matched by file permission checks. |
| `//path` prefix | Absolute filesystem path (`Edit(//secrets/**)`). |
| `/path` (single slash) | Anchored at the rule's source; for `allowedTools`/`disallowedTools` that is the session cwd. |
| `"*"` (deny) | Removes every tool definition. |
| `mcp__server__*`, `mcp__github__get_*` | MCP allow rules: allowed only after a literal `mcp__<server>__` prefix with a glob-free server segment. |
| `mcp__server`, `mcp__server__*`, `mcp__*` (in `AgentDefinition.disallowedTools`) | Remove every tool from the named server / all MCP tools. |
| `allowedTools: ["*"]` / `["mcp__*"]` | **Ignored** — unanchored allows never auto-approve. |

### 10.2 Merge semantics with `settings` (`SDK-TYPED` JSDoc)

When `settings` is inline (object or JSON string, **not** a file path) and has its own `sandbox` block, `sandbox` merges into it:

- A value `sandbox` sets replaces the value at the same path; a value it does not set is kept.
- Two exceptions: `filesystem.disabled: true` is **dropped** when `sandbox` sets `filesystem` or a `credentials.files` deny entry; `network.httpProxyPort`/`socksProxyPort` is **dropped** when `sandbox` sets `network.allowedDomains`, a `deniedDomains` entry, or `strictAllowlist: true` without setting that port itself.
- Nested objects merge key by key, **except** `ripgrep` and `network.tlsTerminate`, which `sandbox` replaces whole.
- Restriction lists (`filesystem.denyRead`, `filesystem.denyWrite`, `network.deniedDomains`, `credentials.files`, `credentials.envVars`) **combine**; a `deny` from either side wins over a `mask` for the same path/variable.
- A `settings` **file path** cannot be combined with `sandbox`.

Additionally: filesystem/network restrictions also come from `Read`, `Edit` and `WebFetch` permission rules, and Claude Code applies **both**.
