#### 3.2 `httpapi-v2-question-live.test.ts(223)` — root cause (fix is not in the test file)

**Exact reproduction** (in-process, production route tree + production authorization middleware,
`HttpApiApp.createRoutes()` with `ConfigProvider.fromUnknown({ OPENCODE_SERVER_PASSWORD: "" })`):

1. `POST /provider/doctor/offline` to `http://untrusted.invalid/...` with **no** `authorization` header →

is not a trusted loopback peer). Therefore the 200 in (2) can only come from
`ServerAuth.authenticatedUsername()` → `ServerAuth.authorized()` accepting an *empty configured*
password as a valid credential.

`Option.isSome(config.password) && credentials.password === config.password`, so with

consults `authenticatedUsername()` even when `required(config)` is false. The reference implementation in
`packages/server/src/middleware/authorization.ts` does this correctly (`if (!ServerAuth.required(config))
{ localPeer ? host_os : no principal }`) and is not affected. `ServerAuth.header()` also treats an empty
password as absent, confirming the intended semantics.

`packages/opencode/src/{auth,provider,question}/**`):**

export function authorized(credentials: DecodedCredentials, config: Info) {
