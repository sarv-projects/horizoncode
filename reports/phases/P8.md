### 2. RC0 attestation — cryptographic verification audit and result

**Before:** `source_signature_digest` was validated only as `sha256:<64 hex>`
syntax. A structurally perfect attestation therefore "verified" without any key.

**After:** `attestation_covers` requires `verify_attestation`, which accepts only
when **all** hold: (a) `source` is in `TRUSTED_ATTESTATION_SOURCES`; (b) a
verifier is registered for that exact source in `TRUSTED_ATTESTATION_VERIFIERS`;
(c) `source_signature_digest` equals the SHA-256 of `attestation_payload`
(domain-separated canonical JSON over source, commit, Session/Run joins, exact
Session→PID/start-time generations, HostRun receipt refs, independent-verifier
evidence refs, OwnerLog event digests); (d) `source_signature` parses as
`hmac-sha256:<64 hex>` and the registered verifier's constant-time MAC over that
exact payload matches. Key material is loadable only from a repository-contained,
no-follow, single-link, `0o600`, 32–64-byte, non-zero file
(`load_attestation_key`); `hmac_sha256_verifier` refuses any key that is not
exactly 32 bytes.

**Public-key option: not implemented, deliberately.** The Python stdlib has no
vetted Ed25519/RSA verifier, and hand-rolling asymmetric verification or adding a
new crypto dependency without authorization is not acceptable for a trust gate.
`ATTESTATION_SIGNATURE_ALGORITHMS` therefore contains only `hmac-sha256`; an
`ed25519:`/foreign algorithm is rejected as unsupported rather than trusted.
`hmac-sha256` is a shared-secret MAC: it proves possession of a locally
provisioned key by the same local user, **not** OS-verified Session ownership and
not an independent verifier verdict. The production allowlist and verifier
registry remain **empty**, so no source can attest, RC0 stays **NOT_ATTESTED**,
and every preflight/capture record stays `release_eligible: false`. No key, key
id, or source name was invented.

Negatives now covered (all asserted to return False/no-attestation): missing or
untyped attestation; stale commit; missing Session→PID/start generation; wrong
generation; foreign Session/Run; foreign key; forged MAC hex; payload-digest
mismatch; any authority-bearing field tampered after signing; unsupported
algorithm; source revoked from the allowlist; allowlisted source with no
registered verifier; verifier raising/returning non-`True`; insecure (group/other
readable), oversized, short, all-zero, symlinked, missing, traversal or
outside-repository key paths; and a constructor-level inconsistency between the
declared signature digest and the signed payload.
