### 2. Root cause and the P7-owned narrow fix (test-first)

`agent.ts:222-227` read `PluginV2.Service` and `Reference.Service` **inside** the `InstanceState`

and not P2 dispatch code**: the same file's own contract test
(`test/effect/instance-state.test.ts`, "serves construction-time initializer services at lookup
time") proves the cache retains construction context.

**RED — new P7-owned `packages/opencode/test/agent/agent-node-deps.test.ts`** (2 cases):
1. *`Agent.state builds when the location map does not expose PluginV2/Reference`* — a consumer
   graph whose `LocationServiceMap` replacement supplies only what the caller needs, with

   `Agent.state (instance-state.ts:38 → agent.ts:215)`, `1 pass / 1 fail`.
2. *`Agent.state whitelists reference directories when the location map exposes Reference`* —
   a location layer that does expose `PluginV2` (mocked `wait`) + `Reference` (materialised
   `reference-docs`), asserting `external_directory` evaluates `allow` for the reference path and
   stays `ask` for the instance's own unlisted path. Green before and after; it locks the
   behaviour so the fix cannot silently delete the whitelist.

**Why not the two previously reported candidates** (both rejected against the file's own
`LayerNode` convention, no new mechanism invented):
- *Add `PluginV2.node` / `Reference.node` to `Agent.node` deps*: `PluginV2.node → SkillV2.node →
  Location.node` (`packages/core/src/skill.ts:261`) is **unbound**, and `LayerNode.compile` throws
  `Unbound layer node` for it. Every root that compiles `Agent.node` without a `Location`
  replacement — `task.test.ts`, `agent.test.ts`, `agent-node-deps.test.ts` — would die at module
  load. Confirmed by reading `layer-node.ts:250-272` and the dep closure; not applied.
- *Hoist the requires out of the initializer*: the layer build context is the same context that
  lacks them (it only has `Config, Auth, Plugin, Skill, Provider, LocationServiceMap`), so the
  failure would move from lookup to build and get *worse*.

**Fix applied** (`packages/opencode/src/agent/agent.ts`, references branch only — 8 lines):

```ts
const plugin = yield* Effect.serviceOption(PluginV2.Service)
const reference = yield* Effect.serviceOption(Reference.Service)
if (Option.isNone(plugin) || Option.isNone(reference)) return [] as string[]
yield* plugin.value.wait(PluginV2.ID.make("core/config-reference"))

```

`Effect.serviceOption` is already the file's own idiom (`agent.ts:618`). The reads stay inside the
`Effect.provide(locations.get(ref))` block, so production is byte-for-byte the same path whenever
the location map materialises the services; a map that does not expose them has no materialised
reference set to whitelist, and the default `ask` rule keeps governing those paths — **fail-closed
for permissions, no allow ever widens**. `Agent.node` deps are unchanged.
