### Disposition decision (from the live state machine, not a new policy)

`mark_external_editor_dispatching` is the atomic PREPARED→RUNNING fence whose
doc contract states "From this atomic point onward, a missing host response is
UNKNOWN and can never trigger a relaunch" — i.e. the fence commits **before**
any spawn. Therefore a durable row still in `PREPARED` proves no process was
ever created in any mode:

- **Prepared-but-unspawned cancellation is deterministic for Full Access.**
  `cancel_prepared_external_editor` no longer demands a cgroup identity. With a
  NULL identity it mints the deterministic
  `horizoncode.external-editor.pre-dispatch-cancel.v1` proof (new
  `editor_pre_dispatch_cancel_digest`, domain-separated from
  supervised-tree quiescence so it can never be mistaken for containment
  evidence), settles CANCELLED with a receipt, and settles the challenge
  SETTLED — all in the existing single transaction with the existing one-use
  `status='PREPARED'` guards. This closes the previously UNKNOWN-only path.
- **Post-dispatch Full Access stays UNKNOWN/no-replay** (unchanged): the
  RUNNING transition crosses the fence, so restart cannot prove absence and
  never fabricates a receipt.
- **Confined cancel now revalidates before killing.** The old code killed
  whatever cgroup the stored identity blob named without checking it against
  the row; it now requires `effect_id`/`execution_id`/`process_kind` to match
  the durable row before any `kill_and_confirm_empty`, else fail closed
  UNKNOWN. (Defense in depth: the blob was validated at prepare, but the
