## Open findings and delivery order

The deduplicated source/design findings live in [ARCH/24 Architecture Review](ARCH/24-ARCHITECTURE-REVIEW.md), F-01..F-66 (`F-65` and `F-66` were measured by the first test execution; see AX-354/AX-355). Highest-risk source/design findings: audit verify mutates its input through the access path; read/head/enumeration errors can be mistaken for empty state; audit locking is process-local; multi-file patch applies incrementally; worker/operator control-state isolation has no accepted platform evidence; controller interfaces must not accept caller-authored principals; goal approval needs a durable challenge and idempotent crash recovery across reservations and process launch; cancellation needs explicit typed targets and per-scope fencing/reconciliation; session artifacts need bounded immutable storage; provider truncation needs evidence-backed, side-effect-safe recovery; canonical session logs are unbounded, inspection can mutate/truncate them, and listing can hide store failures. Platform claims differ; Windows confined execution is unavailable; no platform acceptance ran in this audit.

The durable task DAG, controller, spec/evidence gate, atomic budgets, effect reconciliation, accurate peer quotas, interactive TUI/settings/commands, ACP client and safe agent directory are target design rather than present source behavior. User-selected laptop/workstation or self-managed server is in scope; HorizonCode-hosted service and remote UI/SSH attachment are not. SSH preference applies to Git.

**Implementation entry point (updated 2026-09-28).** The first wave is implemented: AX-353 (typed enumeration), AX-351's read-only slice, AX-352's session durability profile, AX-346's read/write integrity slice, and AX-122's determinism/crash infrastructure.
