## HLD and LLD observations

The public subagent lifecycle API exposes typed immutable request/handle/status/result/cancel/reconnect records and explicit states including `UNKNOWN`. It validates bounded goal/context/metadata sizes, toolset names, and rejects unsupported per-launch working-directory/tool-block/timeout overrides. [`subagent_lifecycle.py`](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/agent/subagent_lifecycle.py#L36-L149), [validation](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/agent/subagent_lifecycle.py#L200-L235). However the backing record registry, correlations, executor, and secret are process globals; `launch()` records work in memory and submits an in-process future. `reconnect()` returns unavailable when the registry has no entry; the service's own contract says a serialized handle cannot reconnect after a restart rather than relaunching. [`SubagentLifecycleService`](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/agent/subagent_lifecycle.py#L153-L160), [launch and in-memory record](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/agent/subagent_lifecycle.py#L237-L301), [reconnect](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/agent/subagent_lifecycle.py#L328-L336).

Provider backend registries support global and per-profile scoped implementations, normalized lookup, lock protection, plugin snapshot/restore, and a generation fingerprint. [`provider_registry.py`](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/agent/provider_registry.py#L27-L128), [restore/generation export](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/agent/provider_registry.py#L130-L170). This supports provider/tool extension, but is not a provider capability proof or immutable adapter-build provenance record.

The gateway has a SQLite `delivery_obligations` ledger with `pending → attempting → delivered/failed` checkpoints. It distinguishes never-started from ambiguous in-flight sends; recovery marks a possible duplicate visibly and has bounded attempts/retention. The module states this ledger is best effort and must never block a send, so it improves honest at-least-once delivery but does not make the response effect atomic with the remote platform. [`delivery_ledger.py`](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/gateway/delivery_ledger.py#L1-L10), [bounded retry policy](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/gateway/delivery_ledger.py#L31-L70), [SQLite table and operations](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/gateway/delivery_ledger.py#L179-L212), [record/transition functions](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/gateway/delivery_ledger.py#L270-L318).

Gateway session routing stores a primary routing index in `state.db` and retains `sessions.json` as a legacy mirror. [`session_persistence.py`](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/gateway/session_persistence.py#L1-L28), [database-first load/persist paths](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/gateway/session_persistence.py#L255-L290), [routing writes](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/gateway/session_persistence.py#L442-L513). Shared-listener ingress routes explicit named profiles and returns 404 when that profile has no adapter for a path, rather than falling through to another profile's adapter. [`shared_ingress.py`](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/gateway/platforms/shared_ingress.py#L1-L18), [profile dispatch](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/gateway/platforms/shared_ingress.py#L109-L150).

The reviewed tool executor path has tool-scope blocks and an authorization gate passed through execution middleware; approval waits are treated specially in batch deadlines. [`tool_executor.py`](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/agent/tool_executor.py#L482-L550), [guarded dispatch](https://github.com/NousResearch/hermes-agent/blob/ea114c3e98c3339e13004adfc6098cf28ed7d754/agent/tool_executor.py#L687-L806). ## HorizonCode delta disposition

- **Already covered:** Durable child identity and task truth are separate in HorizonCode: Task DAG completion requires independent current-revision verification, while Thread/WorkerExecution records preserve external lifecycle identity. Horizon also keeps a durable Run outbox/receipt model and treats uncertain external effects as `UNKNOWN`. See `ARCH/execution/LONG-HORIZON.md`, `ARCH/product/ARTIFACTS.md`, `ARCH/integrations/CONTROL-API.md`, and `research docs/tests.md` recovery matrices.
- **Add:** No new architecture subsystem. Keep the test that a serialized child handle with no durable roster resolves to `UNKNOWN` after restart and is never relaunched on reconnect; the same invariant is already specified under AX-359. The gateway delivery ledger provides an additional concrete fixture for an ambiguous send after `attempting`, including user-visible duplicate marking, if outbound control-plane delivery is implemented; existing test plans already require idempotent receipts and ambiguity recovery.
- **Reject:** Do not count process-global subagent handles as durable child execution, and do not interpret delivery ledger success as proof that a user received or read a message. Provider registry generation is not immutable adapter-build/capability provenance.
- **Defer:** Hermes's broad cross-channel gateway, profile multiplexing, and settings/UI surfaces are outside HorizonCode's current terminal-first scope. The exact profile-ingress 404 boundary is relevant only if named multi-profile listeners become a requirement.

The coverage is intentionally focused; the large agent, gateway, channel, UI, tool, provider, and test trees remain mostly unread per the TSV. No code was copied and no upstream tests were executed.
