## Verified source observations

### Persistence and crash recovery

- The SDK `EventLog` is an append-only, file-per-event store. It serializes an event and writes it under a file lock, updates an in-memory sequence/ID index, then advances a filename-based event-count marker. Its documented `LocalFileStore` locking caveat says `flock()` is not reliable on NFS/network filesystems. See [`event_store.py`](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/openhands-sdk/openhands/sdk/conversation/event_store.py#L188-L238) and [class notes](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/openhands-sdk/openhands/sdk/conversation/event_store.py#L27-L37).
- Conversation state writes the event first, then advances the active leaf/HEAD in memory; public state changes serialize `base_state.json` separately. On restart the server recognizes stale `RUNNING`, scans the full event history for unmatched actions (including events beyond a lagging active head), and appends an `AgentErrorEvent` to surface an interrupted tool call. See [`state.py`](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/openhands-sdk/openhands/sdk/conversation/state.py#L315-L338), [snapshot persistence](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/openhands-sdk/openhands/sdk/conversation/state.py#L430-L449), and [server recovery](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/openhands-agent-server/openhands/agent_server/event_service.py#L1195-L1238).
- Server-level `ConversationLease` uses a file lock, owner instance ID, generation, expiry, and optional host/PID liveness to fence writes after takeover. PID checks are same-host only; unknown liveness is treated conservatively as alive. This is useful local ownership machinery, not evidence of a distributed multi-host lease service. See [`conversation_lease.py`](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/openhands-agent-server/openhands/agent_server/conversation_lease.py#L29-L68), [claim logic](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/openhands-agent-server/openhands/agent_server/conversation_lease.py#L101-L168), and [fenced writes](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/openhands-agent-server/openhands/agent_server/conversation_lease.py#L180-L219).
- The targeted tests include restart after non-graceful shutdown, stale-owner rejection, and event-index gaps. They establish selected server/event-store behavior at their checkout, not HorizonCode behavior. See [`test_conversation_service.py`](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/tests/agent_server/test_conversation_service.py#L346-L430), [restart test](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/tests/agent_server/test_conversation_service.py#L813-L850), and [`test_event_store.py`](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/tests/sdk/conversation/test_event_store.py#L229-L263).

**Important semantic limit:** OpenHands records that a tool was interrupted and did not complete. A missing observation does not prove an external side effect did not happen. Horizon's `UNKNOWN` effect state plus reconciliation is the stronger contract; never translate an unmatched tool call into permission to replay a write.

### ACP resume transcript

The SDK includes `render_resume_transcript`, a bounded rendering primitive for bootstrapping a **new ACP session** when the ACP server has lost its stored session. It deduplicates streaming tool-call frames, keeps recent history under a hard character cap, and marks the transcript so the caller can avoid double wrapping. The module explicitly leaves history acquisition, packaging, and provider-specific sanitization to its caller; it renders raw tool input/output and is not itself a recovery controller. See [`resume_transcript.py`](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/openhands-sdk/openhands/sdk/event/resume_transcript.py#L1-L18), [limits and caller obligations](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/openhands-sdk/openhands/sdk/event/resume_transcript.py#L258-L304), and [truncation/dedup implementation](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/openhands-sdk/openhands/sdk/event/resume_transcript.py#L306-L370).

At this pinned revision, repository search found the function definition, package export, and unit tests, but no production caller. Treat it as an available utility, not a proven automatic continuation path. The tests cover message/tool rendering, duplicate tool-call frames, falsey outputs, ordering, and strict truncation bounds; they do not prove that replayed tool text is safe or that side effects reconcile.

### Benchmarks: useful method, narrow claims

The repo has four event-storage scripts: measured lock/write latency from real SWE-Bench trace payloads; replay/index/recovery latency on increasing event counts; event storage footprint; and synthetic `EventLog.append()` growth. The scripts and benchmark description are under [`scripts/event_sourcing_benchmarks/`](https://github.com/OpenHands/software-agent-sdk/tree/71612374a8d3c639909b03613dbecf1ff999d0bd/scripts/event_sourcing_benchmarks).

- The replay/recovery runner separately times directory-name indexing, JSON parsing, and typed event deserialization plus `get_unmatched_actions()`. It does not time the complete production cold-start path, server lease acquisition, state/projection reconstruction, effect reconciliation, or a real killed-process recovery. See [`bench_replay_and_recovery.py`](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/scripts/event_sourcing_benchmarks/bench_replay_and_recovery.py#L65-L139).
- Persist-latency runs time `LocalFileStore.lock()` + `write()` using already-serialized payloads, not the full `EventLog.append()` serialization/index/marker path. The separate append-scaling script does call `EventLog.append()` but uses synthesized ~1.4KB text events. These are complementary microbenchmarks, not end-to-end recovery proof. See [`bench_persist_latency.py`](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/scripts/event_sourcing_benchmarks/bench_persist_latency.py#L27-L57) and [`bench_append_scaling.py`](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/scripts/event_sourcing_benchmarks/bench_append_scaling.py#L1-L82).
- Published data identifies 433 tasks / 39,870 events, trace run ID `21870831025`, and SDK commit `cfe52af`, not this audited SDK HEAD. The benchmark README calls the workload SWE-Bench Verified, while the artifact URL contains `swtbench`; verify the run metadata and dataset identity before reuse. The recorded latency numbers are historical measurements from another source revision/configuration and must not be presented as results for `71612374` or HorizonCode. See the [`benchmark README`](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/scripts/event_sourcing_benchmarks/README.md#L1-L41).
- This benchmark suite measures storage/runtime behavior. It is separate from OpenHands' model/task evaluation pipeline, which the repo documents as spanning `software-agent-sdk`, `OpenHands/evaluation`, and `OpenHands/benchmarks`; the local skill describes triggering/comparing eval runs, not a self-contained benchmark runner in this SDK. See [evaluation infrastructure note](https://github.com/OpenHands/software-agent-sdk/blob/71612374a8d3c639909b03613dbecf1ff999d0bd/.agents/skills/manage-evals/references/eval-infrastructure.md#L1-L18).

## Comparison against HorizonCode at repository HEAD `7e4b03d2d35d4a012827ea3980ec893b91768677`

HorizonCode's design is already stricter for the user’s long-horizon goal: its segmented log/committed-head proposal and separate session/run/audit streams avoid adopting OpenHands' unbounded file-per-event layout; its effect journal and `UNKNOWN` reconciliation avoid assuming interrupted external actions failed; it already calls for crash kill matrices and multi-hour paired agent benchmarks. Relevant current owners are [`ARCH/07`](../../ARCH/07-SESSION.md), [`ARCH/25`](../../ARCH/25-LONG-HORIZON-CONTROL.md), [`AX-350`](../../TODO.md), and [multi-hour tests](../tests.md#multi-hour-reliability-and-resource-benchmarks).

### Adopt / add

1. **Benchmark method, not measurements.** The runtime repository and relevant runner files are now pinned and targeted-reviewed; the external trace identity, corpus terms/license, and reproducible acquisition still need independent verification before reusing that corpus. Keep it a separately labeled storage benchmark reference. For Horizon acceptance, benchmark the actual integrated production path at the exact Horizon revision: append/commit, streaming replay, projection rebuild, bounded storage, cold restart, and process-kill recovery, on both representative short threads and long runs. Preserve paired environmental controls and report percentiles/raw workload inputs. Existing `AX-350`/`AX-330` already cover much of this; this source justifies a cross-check that the measured path is not accidentally reduced to JSON parsing or lock/write microbenchmarks.
2. **Keep bounded recovery summaries separate from canonical history.** A bounded bootstrap transcript can help an external ACP worker whose server-side session is missing, but it must be marked as untrusted derived context, bind to the Horizon Thread/Attempt and committed event head, and never mutate task/effect state. Use the existing history/context/artifact owners; do not add another conversation store. Because OpenHands leaves sanitization to the caller and has no production caller in the inspected tree, do not copy its transcript policy wholesale.

### Do not add / do not copy

- Do not replace Horizon's per-aggregate committed sequence/digest/segment design with filename ordering/count markers or treat a successful file write as a crash-durable commit receipt.
- Do not adopt “no observation means tool did not complete” as an effect result. A process can die after a remote write and before local observation; keep Horizon `UNKNOWN` and reconcile before retry.
- Do not adopt local file leases as distributed ownership. OpenHands' same-host PID liveness and local `FileLock` are narrower than Horizon's target deployment/worker contract.
- Do not advertise the resume transcript utility as working OpenHands automatic resume. It is a renderer utility with explicit caller-owned integration and sanitation.
- Do not reuse the published SWE-Bench storage timings as evidence for either current OpenHands HEAD or HorizonCode.
