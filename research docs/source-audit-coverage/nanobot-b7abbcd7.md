## HLD and LLD observations

Nanobot is a channel/gateway-centered assistant with an async agent core. Its `SpawnTool` carries the active runtime, origin channel/chat/session key, message ID, and current workspace scope into the subagent manager; `wait=false` starts background work and `wait=true` runs an inline consultation. [`spawn.py`](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/agent/tools/spawn.py#L81-L106). The manager caps concurrency with a semaphore, but its running tasks, statuses, and session-to-task index are in process-local dictionaries. Background tasks are created with `asyncio.create_task`; a done callback removes the task and status. [`subagent.py`](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/agent/subagent.py#L155-L170), [spawn and cleanup](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/agent/subagent.py#L238-L300). Cancellation is scoped by the in-memory session index and cancels active asyncio tasks/owned exec sessions. [Cancellation and close](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/agent/subagent.py#L584-L602). The subagent result is announced to the originating channel/session; the reviewed execution assembles a fresh system/user message pair rather than a durable task transcript. [Subagent execution](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/agent/subagent.py#L414-L497).

Session history has a separate `SessionStore` abstraction and JSONL implementation, with session storage placed outside the workspace and runtime checkpoints for in-flight turn state. [`manager.py`](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/session/manager.py#L423-L470), [runtime checkpoint](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/session/manager.py#L1104-L1130). Transcript/session durability therefore does not imply that a child process/task has a durable launch intent, lease, effect receipt, or safe restart continuation.

The message bus separates channel ingress, agent core events, and outbound channel projection, but its inbound and outbound `asyncio.Queue`s have no max size in their constructors. `publish_nowait` retains pending event tasks for a local `drain()` and documents that separate publications can interleave rather than forming a global FIFO. [`queue.py`](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/bus/queue.py#L19-L47), [event dispatch/drain](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/bus/queue.py#L118-L149). Channel adapters authorize inbound senders by wildcard, exact allowlist, or pairing approval before publishing them to the bus. [`BaseChannel`](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/channels/base.py#L237-L290).

The provider factory validates provider/model configuration, resolves backend-specific providers and can wrap the primary with ordered fallback presets; it has a non-networking unconfigured snapshot for first-run UI setup. [`factory.py`](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/providers/factory.py#L76-L120), [fallback construction and unconfigured snapshot](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/providers/factory.py#L263-L317). Provider internals and most configuration/settings UI code were only partially inspected.

The sandbox source has Linux bubblewrap and macOS Seatbelt paths. Bubblewrap mounts the workspace writable and media read-only but does not pass `--unshare-net`; Seatbelt comments likewise state network is unrestricted. This is a declared local profile boundary, not no-network confinement. [`sandbox.py`](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/agent/tools/sandbox.py#L56-L101), [Seatbelt network and rules](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/agent/tools/sandbox.py#L192-L206), [filesystem rules](https://github.com/HKUDS/nanobot/blob/b7abbcd70b9d21bb3f7052699195eb39693b7615/nanobot/agent/tools/sandbox.py#L258-L273).

## HorizonCode delta disposition

- **Already covered:** The core design already distinguishes Thread transcript history from Task/Attempt/WorkerExecution state; restart reconciliation preserves unknown child/effect outcomes; provider adapters are capability-scoped; permissions remain behind the central guard; mailbox delivery has bounded messages and receipts. See `ARCH/execution/LONG-HORIZON.md`, `ARCH/product/AGENT-MESSAGING.md`, `ARCH/core/PROVIDERS.md`, and `research docs/tests.md` cases for missing child roster after restart and unknown work outcomes.
- **Add:** No new HLD subsystem. Retain the already-planned regression case that a durable session/transcript plus a missing process-local child roster is `UNKNOWN`, never “no child” or completed; `research docs/tests.md` already calls this out in the AX-359 recovery cases. The unbounded bus queues are a useful future stress-test pattern only if Horizon's bounded Run event/control stream implementation exhibits a matching risk; no duplicate queue owner should be added.
- **Reject:** Do not equate `SessionStore` persistence with child execution recovery or task verification. Do not infer a network-isolated sandbox from the workspace mount; the inspected code explicitly permits networking.
- **Defer:** Nanobot's channel allowlists, gateway management, rich settings UI, and provider breadth do not change the terminal-first product scope. Consider them only if a HorizonCode gateway/channel adapter becomes an approved requirement.

The inventory is not an exhaustive source review; unreviewed settings, channel adapters, provider implementations, and tests remain listed as `UNREAD`. No code was copied and no upstream tests were executed.
