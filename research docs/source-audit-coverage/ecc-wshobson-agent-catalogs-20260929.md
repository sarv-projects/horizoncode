## Findings

### ECC

ECC is a harness-oriented workflow bundle, with substantial authored content plus active local hook scripts. At the pin, its contributor/context instructions describe 68 agents, 292 skills, and 94 legacy command shims; skills are the canonical workflow surface, while commands are in migration/compatibility mode. Agents and skills are Markdown definitions, commands are prompt entry points, rules are persistent guidance, and hooks invoke local lifecycle/quality/telemetry tasks. The same sources are distributed through Claude Code plugin packaging and harness-specific copies/sync paths. Evidence: [AGENTS.md](https://github.com/affaan-m/ECC/blob/d3b8a3e908904e242ed2dbe66af62cca71131419/AGENTS.md), [Claude plugin manifest](https://github.com/affaan-m/ECC/blob/d3b8a3e908904e242ed2dbe66af62cca71131419/.claude-plugin/plugin.json), [Codex plugin manifest](https://github.com/affaan-m/ECC/blob/d3b8a3e908904e242ed2dbe66af62cca71131419/.codex-plugin/plugin.json), [hooks configuration](https://github.com/affaan-m/ECC/blob/d3b8a3e908904e242ed2dbe66af62cca71131419/hooks/hooks.json), and [hook metadata](https://github.com/affaan-m/ECC/blob/d3b8a3e908904e242ed2dbe66af62cca71131419/hooks/hooks.metadata.json).

The useful capability addition is content breadth and ready-made workflow guidance: domain-specific review/build agents, TDD/security/verification/research skills, language/framework playbooks, and hook-based reminders/telemetry. `cost-tracker.js` and `context-budget` material are observations/heuristics; they do not establish provider-measured spend or a cross-provider admission budget. Instructions such as proactive delegation, test-first behavior, and security checklists are prompts and local hooks. They do not by themselves provide HorizonCode's independent task verification, durable orchestration, guard/sandbox effect path, or audited permission enforcement. This boundary matches the existing peer note, which classifies ECC's transcript-derived cost and context estimates as visibility patterns, not enforcement ([existing comparison](../agent-ecosystem-review.md#nanobot-and-ecc-lightweight-telemetry-patterns-limited-attribution)).

ECC's hook configuration includes event/matcher-to-command wiring, profile controls, and scripts; the registration layer is harness-specific and can run local commands. Its `CLAUDE.md` includes a prompt-defense baseline, but prompt wording is not an OS isolation boundary. Treat every bundled instruction and hook as executable/untrusted extension material that HorizonCode would have to inventory, review, scope, and route through its own effect controls. Do not equate AgentShield scan features or hook warnings with runtime containment.

### wshobson/agents

This is primarily a composable plugin catalog and generation/adaptation pipeline. `plugins/` is the source of truth for Markdown agents, skills, commands, references, and assets. The architecture map describes harness adapters that transform metadata and content into native artifact layouts for Codex, Cursor, OpenCode, Copilot, Antigravity, and Pi; it calls out model aliases, tool-name/permission translation, body-size limits, and harness-specific naming rules. Generated outputs are ignored, with native install registries committed as pointers to source. Evidence: [architecture map](https://github.com/wshobson/agents/blob/156b7a5e7a8b93642628a339ee4039c925b34c7f/ARCHITECTURE.md), [adapter base](https://github.com/wshobson/agents/blob/156b7a5e7a8b93642628a339ee4039c925b34c7f/tools/adapters/base.py), [capability matrix](https://github.com/wshobson/agents/blob/156b7a5e7a8b93642628a339ee4039c925b34c7f/tools/adapters/capabilities.py), [generator](https://github.com/wshobson/agents/blob/156b7a5e7a8b93642628a339ee4039c925b34c7f/tools/generate.py), and [generated-output validator](https://github.com/wshobson/agents/blob/156b7a5e7a8b93642628a339ee4039c925b34c7f/tools/validate_generated.py).

A concrete distribution/safety detail from the fully read OpenCode installer: it links generated artifacts into the selected config directory, refuses to overwrite regular user files, requires `--force` to replace a conflicting symlink, and uninstalls only symlinks resolving under the repository's generated output root. The matching unit tests cover idempotence, conflicts, and preserving unrelated files. This is a useful narrow install ownership pattern; it is not a general extension trust or sandbox system. Evidence: [installer](https://github.com/wshobson/agents/blob/156b7a5e7a8b93642628a339ee4039c925b34c7f/tools/install_opencode.py), [installer tests](https://github.com/wshobson/agents/blob/156b7a5e7a8b93642628a339ee4039c925b34c7f/tools/tests/test_install_opencode.py).

The generator/validator tests are intended to exercise output structure, harness-specific remaps, source/output counts, and round-trip conventions. The repository also ships a `plugin-eval` project with static scoring and experimental LLM-judge/Monte-Carlo layers; its published README explicitly says the latter are not validated against human labels. These are source/test claims only: no suite or live CLI was run in this audit. Treat a valid generated manifest, prompt quality score, or successful install as neither permission to execute nor proof of runtime behavior.

## HorizonCode overlap and what is additive

HorizonCode already plans one discovery/catalog source and explicitly calls for skills to remain untrusted instructions, digest-checked activation, bounded progressive loading, and guarded execution for scripts. `AX-110` implements discovery/listing and digest validation; `AX-373` owns model-visible activation/capability inventory; `AX-378` owns the extension manager. See [TODO AX-110](../../TODO.md), [TODO AX-373](../../TODO.md), [TODO AX-378](../../TODO.md), [ARCH/21 Discovery](../../ARCH/21-DISCOVERY.md), and [ARCH/22 Security](../../ARCH/22-SECURITY.md).

- **Direct conceptual overlap:** both repositories supply reusable skill text, specialized-agent profiles, slash/prompt command collections, persistent rules, and curated domain knowledge. ECC's TDD, planning, review, and verification workflows overlap with built-in workflow/agent ambitions even where HorizonCode's implementation is not yet present. wshobson's granular plugin packaging organizes the same content classes. Adding another internal skill/agent/command registry or injecting the whole catalog would create duplicate ownership and context load.
- **Distinct useful capability:** ECC contributes a large, multi-domain content library and some local event-triggered convenience hooks. wshobson contributes an explicit source-to-harness transformation/catalog build with a capability matrix and generated artifact checks. The latter is a useful *design comparison* for adapter capability tests and source/derived artifact drift checks. Neither repository supplies HorizonCode's durable Task/Attempt/Thread control plane or acceptance authority.
- **Avoid duplicate implementation:** HorizonCode should keep one authoritative catalog and one permission/effect pipeline. Do not add ECC hooks as a second scheduler, usage ledger, skill store, or policy engine. Do not add wshobson's generator as a second registry if HorizonCode chooses a native protocol/runtime; only adopt a conversion boundary if the product requirement is truly to import/export these external formats, and keep its capability losses explicit. A curated external-content proposal belongs under AX-378 and requires review of source, version, license, authority, and activation before any installation path.

## Provenance and licensing questions

Both checked-out root `LICENSE` files state MIT. ECC also tracks `skills/taste-application/scripts/LICENSE` with a separately named copyright holder. The wshobson architecture describes two marketplace entries sourced externally via git-subdirectory; their individual code, prompt, and asset licenses were not audited here. In both repositories, `LICENSE` at root alone does not prove every bundled reference, image, script, prompt, model-specific example, or imported upstream fragment has the same provenance. Before adopting or redistributing any content, inspect the exact file's history and origin, nested notices, third-party asset/source licenses, and whether generated forms preserve required notices. No license/provenance clearance is granted by this review.
