## HLD and LLD observations

The reviewed small V3 TypeScript domain surface is a prototype-style in-process swarm model. `SwarmCoordinator` owns agents, metrics, connections, and event emission in Maps/arrays; task assignment sorts by priority and picks the currently lowest count, then concurrent execution uses `Promise.all`. Tasks without an eligible agent are silently omitted from the returned assignments. See pinned [`SwarmCoordinator.ts`](https://github.com/ruvnet/ruflo/blob/fce8e6da5a6edda3791367b244066e6c67730196/v3/src/coordination/application/SwarmCoordinator.ts#L142-L187) and [concurrent execution](https://github.com/ruvnet/ruflo/blob/fce8e6da5a6edda3791367b244066e6c67730196/v3/src/coordination/application/SwarmCoordinator.ts#L261-L287).

The V3 `Agent` runs a supplied callback (if present), waits a priority-derived 1/5/10 ms, and returns a generic completion string; the source explicitly describes actual work as being done by the callback. [`Agent.ts`](https://github.com/ruvnet/ruflo/blob/fce8e6da5a6edda3791367b244066e6c67730196/v3/src/agent-lifecycle/domain/Agent.ts#L43-L105). Its `SQLiteBackend` keeps values in a process-local `Map`; `initialize()` comments that opening SQLite is not implemented, and `close()` clears the Map. [`SQLiteBackend.ts`](https://github.com/ruvnet/ruflo/blob/fce8e6da5a6edda3791367b244066e6c67730196/v3/src/memory/infrastructure/SQLiteBackend.ts#L25-L56). The coordinator's consensus path generates random approve/reject votes and comments that real LLM calls are not implemented. [`SwarmCoordinator.ts`](https://github.com/ruvnet/ruflo/blob/fce8e6da5a6edda3791367b244066e6c67730196/v3/src/coordination/application/SwarmCoordinator.ts#L365-L393).

The MCP agent tool surface validates a small fixed set of agent types and exposes spawn/list/terminate/metrics; it does not itself define HorizonCode-style per-effect approval or an independent task-verification boundary. [`AgentTools.ts`](https://github.com/ruvnet/ruflo/blob/fce8e6da5a6edda3791367b244066e6c67730196/v3/src/infrastructure/mcp/tools/AgentTools.ts#L19-L91). The root Ruflo repository also contains a much larger CLI/package/plugin tree; most of that tracked code was unread, so these observations describe the named V3 files only and should not be generalized to the whole product.

## HorizonCode delta disposition

- **Already covered:** HorizonCode's HLD/LLD keeps durable Run/Task/Attempt state, fenced worker executions, budget reservations, permission checks, and independent verification as the authority. This is stricter than the inspected V3 in-memory task assignment/status path. See `ARCH/execution/LONG-HORIZON.md` task transitions and dispatch/recovery sections and `ARCH/execution/ORCHESTRATION.md`.
- **Reject:** Do not adopt the V3 `SwarmCoordinator` as evidence for durable orchestration, acceptance, or consensus. The source directly shows process-local state and a simulated consensus vote. Do not treat an agent's `completed` return value as Horizon task PASS.
- **Defer:** No new topology/consensus subsystem is justified by these files. Existing worker/peer adapters can represent a separately governed external orchestrator, with HorizonCode remaining the run controller and verifier. Ruflo's broader published CLI, persistence, settings/UI, tool permissions, providers, and failure paths were not covered enough to make positive feature claims or propose a source delta.
- **Add:** None from this bounded V3 source slice. This is not a claim that the full 2,993-file inventory was audited; the ledger records the limitation per path.

No source was copied. All observations above are static source reading at the pinned revision, not runtime verification.
