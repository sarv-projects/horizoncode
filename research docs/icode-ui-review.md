# iCode TUI and interaction-pattern review

Reviewed at `openJiuwen-ai/iCode` commit
[`bb45692104bc1d26882729e90fc145e3a114e066`](https://github.com/openJiuwen-ai/iCode/tree/bb45692104bc1d26882729e90fc145e3a114e066).

workflow files below, not a claim that every repository file or line was audited.
The findings describe observed iCode behavior; HorizonCode's requirements and
controllers remain authoritative.

## Explicit non-adoptions and source corrections

- iCode's **Explore Agent** is a read-only agent profile for repository analysis, not
  a filesystem Explorer. See [`Explore.yaml`](https://github.com/openJiuwen-ai/iCode/blob/bb45692104bc1d26882729e90fc145e3a114e066/src/chrys/service/profiles/agents/builtins/Explore.yaml).
- The reviewed revision has no general in-app project-file Explorer/opener. `@` is a
  prompt path reference, Ctrl+O edits the prompt, the file picker selects a path for a
  caller, and Trajectory can open a session directory externally. HorizonCode's
  Explorer/file opener is a separate first-party design (`ARCH/product/UI.md`, `AX-208`).
- Do not expose Task, Attempt, Thread, and WorkerExecution as peer rows in the default
  task list; retain their identities and evidence in detail/controller state.
- Do not use iCode's deep agent/MCP/skill configuration forms as HorizonCode's default
  Extensions experience. Do not copy its chat-centric layout or its `bypass` approval
  mode. HorizonCode keeps three panes and its Guard ceilings/scoped approvals.
- This is pattern adaptation only. HorizonCode does not adopt iCode's Python workflow
  runtime as a second runtime or its Textual-specific implementation.

The reference set is iCode-specific; patterns from Codex, OpenCode, and Grok Build
remain separately pinned in [`docs/research/SOURCE-TRACEABILITY.md`](../docs/research/SOURCE-TRACEABILITY.md) and their
focused research notes. All implementations, test plans, and acceptance evidence are
HorizonCode-owned.
